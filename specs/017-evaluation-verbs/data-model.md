# Data Model: Evaluation Verbs

All wire models live in `packages/coire-core/src/coire_core/models/evaluation.py` or `models/training.py` with schedule/value types in `models/training_evaluation.py`. Use `extra="forbid"`, finite bounded floats, aware UTC times, strict counts, bounded strings/lists and existing SHA-256/ULID types. Existing model, variant, adapter, node and agent-run IDs are UUIDs; new evaluation/group/result IDs are ULIDs. No engine path is a public selector.

## Suite and catalog

`EvaluationSuiteTemplate` is shipped immutable data: template slug, template version, kind (`harness|task|judge`), mode (`capability|deterministic|rubric|pairwise`), case IDs/content digests, declarative scorer version, allowed configuration, supported workload version and default bounds. The API and Studio runner verify the same package data digest.

`EvaluationSuiteRow` / `EvaluationSuite` is an admin-registered immutable version: suite slug, positive version, template reference/digest, cases digest, scorer digest, content digest, generation settings, timeout, case/token/byte bounds, rubric/scoring definitions, optional exact judge target/settings, registering owner and timestamp (the built-in harness seed has explicit system/migration attribution and no fabricated user). Unique `(suite_id, version)`; registering the same version with different content is 409. Judges are required only for judge suites; selecting arbitrary remote files, prompts, commands or scorer modules is invalid. Registration of a changed judge requires a new suite version. A separate mutable retirement marker stops future admission without editing the definition. Retirement is audited.

## Evaluation group

`EvaluationGroupRow` / `EvaluationGroup`: ULID, active admin owner UUID, origin (`manual|training_checkpoint|training_final|measurement`), optional job/checkpoint/update/attempt, frozen base/candidate targets, creation time and linked run IDs. Automatic group identity is unique for its training boundary and resolved schedule digest. Status is a projection from run states, not a second mutable score. A manual two-subject run creates its group transactionally; unrelated historical results can be compared through a read-only compatibility endpoint.

## Evaluation run

`EvaluationRunRow` / `EvaluationRun`: ULID, group ID, suite/version/content snapshot, one or two ordered exact subjects (harness exactly one; pairwise exactly two), optional exact judge, owner and submitting credential/audit reference, source rerun ID, canonical request hash, idempotency key hash, version, current phase/state, queue/execution deadlines, created/started/finished times, cleanup state, failure reason, training data reference snapshot and evidence quota reservation.

`EvaluationTargetSnapshot`: existing `InferenceTarget` plus registry selector, display labels, retired flag at read time, base lineage/model identity and runtime/tokenizer/template/capability digests. Snapshot allows historical reads after retirement. New runs re-resolve readiness; they never use a stale snapshot as permission to load.

States: `queued → preparing → reserving → running → collecting → succeeded|failed|timed_out`; cancellation from any nonterminal state goes through `cancelling → cancelled` after stop proof. Capacity waits remain `reserving` with `capacity_busy`. Failed/time-out runs may have `cleanup_state=pending|unresolved`; their owned reservations remain and parent training cannot resume until cleanup is complete. Outcome/reason is separate from phase (`base|candidate|judge|harness|contamination|cleanup`).

Terminal result is immutable; operational cleanup observation may advance separately without rewriting it. Mutable retirement, evidence-availability and cleanup status are read-time projections excluded from the canonical result digest. Low task/rubric score is a successful measured execution. Harness verdict is stored separately from run success. Failure reason enums include model_unavailable, judge_unavailable, authorization_revoked, malformed_judge, invalid_evidence, runtime_mismatch, evidence_unavailable, capacity_timeout, admission_disabled, execution_timeout, latency_breach, memory_breach, telemetry_stale and cancelled; client responses are content-free.

Unique `(owner_id, idempotency_key_hash)` binds to canonical request. Same key/body returns the existing receipt; different body is 409. Explicit rerun requires a new key and creates a new ID. Finalize uses optimistic run version/fence and a unique result per run.

## Attempt / execution evidence

`EvaluationAttemptRow`: UUID, evaluation ID, phase, ordinal, durable child agent-run UUID, generation/fence, node UUID, reserved instance/placement references, granted target digest, workspace/output references, deadlines, lifecycle observation and collected digest. Unique child run and `(evaluation_id, phase, ordinal)`; restart observes before resubmitting. Multiple sequential phases may use different Studios, recorded separately.

`EvaluationWorkload` and `EvaluationWorkerResult` are strict transport types. Workload binds run/attempt/phase/fence, suite and cases, allowed target, settings, input evidence digests and bounds. Result repeats binding and contains complete typed case evidence, actual model/runtime identity, token counts and timings. Missing, duplicate, unexpected or out-of-range cases are invalid evidence; a caller cannot substitute a ready target or supply an authoritative verdict. Authoritative harness verification requires every category's actual case evidence.

## Immutable result and comparison

`EvaluationResultRow` / `EvaluationResult`: ULID, unique run ID, terminal outcome/reason, ordered per-subject case results, nullable subject aggregates, optional pairwise result, nullable harness verdict/legacy harness record link, complete provenance snapshot, contamination report, private evidence metadata and canonical result digest. Failed/cancelled/timed-out executions have no aggregate; completed cases may remain labeled partial for inspection but never appear as a valid total.

Task assertions return boolean per case; aggregate is passed cases / total. A case with multiple assertions passes only when all pass. Rubric case scores are integer 0–4 per fixed equally weighted dimension; aggregate is mean(all dimensions/cases)/4. Pairwise case evidence contains two reversed presentations with A/B/tie; consistent preferences map to the same target, otherwise the case is a tie. Aggregate is wins/ties/losses plus each target's preference share `(wins + 0.5*ties)/cases`, labeled preference, not independent quality. Harness preserves current category ratios and minimum category ≥0.8 pass gate. Completed harness failure revokes exact verification; infrastructure failure does not.

`EvaluationComparison`: explicit result/subject references, compatibility boolean, bounded mismatch reason list, per-case/aggregate task or rubric deltas when compatible, pairwise preference summary when applicable. Compatibility requires matching suite/content/cases/scorer, decoding including seed, tokenizer/template/capability, runtime/engine/harness and judge/rubric/order-policy identities. Node/time/subject identities may differ and remain visible. Missing legacy provenance is non-comparable. No significance claim. Base/adapter linkage is verified against exact base identity, not display names.

## Contamination and private evidence

`EvaluationContamination`: algorithm `input-exact-v1`, status `clean|overlap|unavailable|not_applicable`, source/split/mixture digests, selected train-row count through the evaluated completed update, checked case count, hit count, matched case IDs and reason. Normalize input-only text/messages/tool schemas from the existing canonical training types using a fixed serialization; exclude reference/completion text, preserve content whitespace and message order. Traverse actual mixture-selected rows consumed through the evaluated completed update, reconstructed from recorded seed/sampler/cursor; do not compare only the validation split or entire source as if selected. Exact projection equality is the only claim. Unsupported formats or missing permitted bytes yield unavailable. All preparation/scanning/scoring occurs in the Studio workload; core sends bounded existing dataset grants and stores metadata. No raw training rows in results.

`EvaluationEvidenceRow`: UUID, run/attempt owner, generated opaque storage key, digest, bytes, created/expiry timestamps, pin-until deadline, availability (`present|expired|missing`), quota reservation. Store ≤8 MiB/run with aggregate reserved quota ≤1 GiB. Raw bytes expire after seven days by default; active phases can pin only to their fixed deadline. Evidence expiry updates availability, not the immutable result digest; historical metadata remains. Admin reads are authenticated and return 410 after expiry. Staging verifies digests and path containment; Studio scratch disappears after collection/cancel. Unknown cleanup remains observable.

## Training v2 and automatic trigger

Keep `TrainingSpec` and `ResolvedTrainingSpec` v1 serialization unchanged. Add `TrainingSpecV2(schema_version=2)` with the same common fields and `TrainingEvaluationV2` retaining loss settings plus `suites: list[TrainingSuiteSchedule]` (1–4). Each schedule references an immutable suite ID/version and sorted unique `checkpoint_updates` (0–32, all >0 and < final optim.updates, aligned to output checkpoint cadence). Final success always evaluates every declared suite. No client-provided resolved judge or digest is trusted; preflight freezes them into separate `ResolvedTrainingSpecV2`. A discriminated `TrainingSpecDocument` and `ResolvedTrainingSpecDocument` are used in envelopes without coercing stored v1 objects.

`TrainingEvaluationTriggerRow`: UUID, job ID, boundary kind, committed checkpoint ID/digest, update, resolved schedule digest, group ID, phase, evaluation pause command/version/fence, protected artifact IDs, creation/deadline/cleanup times and resume disposition. Unique `(job_id, boundary_kind, completed_update, schedule_digest)`; the retained checkpoint ID is immutable on that obligation plus group link. Checkpoint and final boundary cannot double-schedule final update. Trigger records all suites due at that boundary and creates child runs transactionally/idempotently when queue/evidence quota permits. The obligation itself persists even when admission is disabled or full, without making training completion fail. Its acceptance-time queue deadline bounds waiting; expiry creates explicit per-suite failure summaries without allocating a worker or raw evidence quota. New v2 training submission is refused while evaluation admission is disabled; previously accepted v2 training retains its durable obligations. Failed/cancelled training creates no final trigger; partial checkpoint results remain history.

Trigger phases: `pending_pause → stopping_trainers → preparing_adapter → evaluating → cleaning → resume_pending → complete`; failures go through cleaning then either safe resume or explicit operator pause according to live intent/admission. An evaluation failure alone can resume still-authorized training after cleanup; inability to reacquire safe capacity stays visibly paused. Admin pause/cancel supersedes automatic resume. Recovery matches exact job version, checkpoint and pause owner; never converts a protective pause to an evaluation pause.

Pins reference existing checkpoint/adapter storage quota. At most one pending boundary per job; existing three-checkpoint and byte caps remain. Internal checkpoint adapters carry `purpose=evaluation`/trigger ownership, remain private and are excluded from normal pickers and publishing. User promotion remains a separate curated adapter operation. Successful final adapters remain ordinary output adapters.

## Coexistence measurements and event history

`EvaluationMeasurementRow` / `EvaluationMeasurement`: UUID, admin owner, exact requested evaluation workload and resident targets, resource/hardware/runtime fingerprints, baseline/mixed phase samples/counts, failures, memory/swap/thermal/gateway measurements, state, timestamps and evidence digest. `EvaluationCoexistenceProfileRow`: immutable passing report digest, exact workload/resident/hardware/runtime keys and expiry ≤24h; invalidated marker outside the report. Admission matches the full fingerprint. Measurement is explicit admin-controlled work, not an implicit side effect of ordinary submission.

`EvaluationEventRow`: run ID, monotonic sequence, state/version/phase, timestamp and typed content-free payload. `EvaluationGroupEventRow` has a separate group sequence and content-free affected-run receipt. A group-owned sequence counter changes under its lock; frozen group identity excludes that counter. Each history retains at most 1,000 events independently. SSE honors Last-Event-ID; bounded retention returns a reset snapshot rather than gaps concealed as continuity. Existing training terminal streams may close before final evaluation completes; evaluation/group streams remain the authoritative subscription for those results.

## Migration and retention rules

One `0032_evaluation_verbs.py` migration creates these tables, constraints/indexes and minimal evaluation pause/purpose references on existing training/run rows. New immutable rows prevent cascade deletion of history; snapshot labels/identities survive retirement. Do not alter or rehash old training JSON, add defaults to old hashed shapes, overwrite harness rows or repurpose `TrainingAdapterRow.evaluation_id`. Up/down tests include populated 016 state. Downgrade is allowed only after evaluation work/pins are drained; normal binary rollback retains additive tables and history. Task/judge results never update registry routing or publishing columns.
