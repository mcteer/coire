# Native Chat operations

The native Chat API is gated by `COIRE_CHAT_ENABLED` and defaults to off while feature 014 is built. Set `COIRE_CHAT_PUBLIC_ORIGIN` to the exact HTTPS browser origin (scheme, host and optional port; no trailing slash) before enabling it. Local development may use `http://localhost` or `http://127.0.0.1` with a port. Browser writes with another or missing Origin are refused; user-owned API keys with `chat` scope use bearer authentication.

Inspect picker/create request outcomes in the **Coire Chat** Grafana dashboard or `coire_chat_requests_total{operation,outcome}`. Trace spans are `coire.api.chat.picker` and `coire.api.chat.create`; logs include only operation, user ID, conversation ID or count. `CoireChatApiFailures` alerts on unexpected route failures. A 404 for a selected model can mean absent, unpublished, unready or not entitled; do not expose which case to callers.

To stop new native Chat admission, set `COIRE_CHAT_ENABLED=false` and redeploy the API. This hides native routes but leaves chat reconciliation and cleanup running so existing deletion deadlines still advance; it does not change the existing `/v1` gateway. Restore the previous API image and configuration to roll back the current runtime; owner-scoped drafts, messages, turns and events remain in the `0015_chat_conversations` schema, `0016_chat_purge_marker` tracks completed cleanup and `0017_chat_message_context` stores selected file modes and prompt snapshots. Before downgrading `0015`, export and delete all chat content per the migration guard and the release backup procedure.

Text turns now persist their accepted event before the SSE response, and each status, answer delta and terminal event before emission. Inspect a turn using the owner-scoped `GET /api/v1/chat/conversations/{conversation_id}/turns/{turn_id}` route. The stream uses the existing gateway proxy and memory lease; `coire_chat_requests_total{operation="send_terminal",outcome=...}` distinguishes completed, failed, stopped and interrupted turns. A failed, stopped or interrupted answer retains its saved partial text. Duplicate send IDs with the same body follow saved events and never start a second engine request. The owner can request Stop with `POST /api/v1/chat/conversations/{conversation_id}/turns/{turn_id}/stop` and `{"reason":"user_stop"}`; inspect the turn until it reaches `stopped` or another terminal state. Stop requests and outcomes are visible through `coire_chat_requests_total{operation="stop",outcome=...}` and `coire_chat_requests_total{operation="send_terminal",outcome="stopped"}`. A Stop closes the controlling gateway stream and releases its engine slot and lease while preserving saved partial text. Native Chat remains default-off until deletion/purge and browser recovery are complete in later 014 children.

An admitted plain-chat turn has a 30-second process lease renewed every five seconds. When enabled, API startup and five-second maintenance passes reconcile expired turns to a saved `interrupted` terminal, or `stopped` if Stop was already requested. This clears the active-turn slot and retains the saved partial answer. Inspect `coire_chat_requests_total{operation="reconcile",outcome=...}` and the **Coire Chat** dashboard; `CoireChatApiFailures` covers failed passes. A recovered turn is never resumed automatically. If recovery repeatedly fails, inspect API logs by turn ID and restore database connectivity; disable Chat admission with `COIRE_CHAT_ENABLED=false` while fixing the failure. The database migration remains reversible only after chat content is exported and removed.

Owner viewers can follow `GET /api/v1/chat/conversations/{conversation_id}/events` with a conversation-scoped `Last-Event-ID` header. The stream rechecks credentials and sends a replacement `snapshot` if older events expired; inspect `coire_chat_requests_total{operation="observe"}`. A viewer has no generation or Stop authority through this stream. Browser tab reconciliation is added in a later 014 child.

Conversation title/model edits use owner-scoped `PATCH /api/v1/chat/conversations/{conversation_id}` with `expected_revision`. A successful edit increments revision and emits `conversation.updated`; stale revisions return 409 and the browser refreshes history before retry. Inspect `coire_chat_requests_total{operation="update",outcome=...}`. Code-mode transitions remain disabled until the coding path is complete.

Owner deletion uses `DELETE /api/v1/chat/conversations/{conversation_id}` with `expected_revision`. The first accepted request tombstones immediately, requests Stop for an active text turn and emits a content-free deletion event to already connected observers. Reads are denied after tombstoning; a repeat owner delete returns the original purge deadline. Inspect `coire_chat_requests_total{operation="delete",outcome=...}`. After five minutes, maintenance purges messages, turns, events and quota rows, scrubs the title/model selection, and writes `purged_at` once file jobs and originals are gone; inspect `coire_chat_requests_total{operation="purge",outcome=...}` and the **Coire Chat** dashboard. Conversations with active turns wait for safe cleanup. Keep `COIRE_CHAT_ENABLED=false` until the remaining Chat gates pass.

Maintenance also removes expired 24-hour event rows in batches of 1000. A viewer whose cursor has expired receives a replacement snapshot. The **Coire Chat** dashboard shows `coire_chat_purge_oldest_seconds`; `CoireChatPurgeOverdue` alerts when deleted content has waited past the 24-hour deadline. If it fires, inspect the API maintenance logs and the pending conversations' attachment/active-turn state, then complete safe file cleanup before clearing their purge markers. Keep Chat admission disabled until original/derived blob cleanup is verified.

The isolated CPU file processor handles bounded UTF-8, PDFium extraction/page rendering and Pillow still-image normalization. It reads only generated original IDs, verifies SHA-256, and writes generated job/asset PNG keys without overwriting prior assets. To diagnose parser fixtures locally, run `uv run pytest -q apps/coire-file-worker/tests/test_processor.py`; stable `FileProcessingError.code` values distinguish invalid input, limit, digest, deadline and storage failures without exposing file content.

PDFium's password-required failure is `pdf_password_required`; the browser says the PDF is password-protected. Malformed PDFs use `invalid_pdf`. The parser tests use small upstream PDFium fixtures for Unicode extraction and password refusal, plus a subprocess that confirms a stuck native call exits the worker with status 124. On an abrupt worker exit, the scheduler's immutable job/status recovery records a visible failure and waits for explicit user retry after output cleanup; it never silently reruns the document.

The private worker service exposes `/health`, `/v1/process`, `/v1/jobs/{job_id}`, `/v1/jobs/{job_id}/cancel` and `/v1/jobs/{job_id}/output` with the dedicated `file_worker_service_token` bearer secret on every route. A job ID binds one immutable request; retrying the same request returns its status, while a different request with that ID returns 409. The service admits one conversion per process and returns 429 when busy. Inspect `coire_file_processing_total{outcome}` and content-free job-ID logs for completed, refused, cancelled or internal failures. Cancellation hides a late result and discards partial generated outputs. A 30-second native-call watchdog exits the sole process if PDFium/Pillow blocks; scheduler recovery treats missing in-memory status after restart as a failed job, never as permission to rerender it. Keep Chat admission disabled until the remaining gates pass.

The worker image now builds as a non-root, shell-free Linux arm64 image with a credentialed local health probe. `COMPOSE_PROFILES=chat-files` opts into its private scheduler network and named original/derived volumes. `coire-file-worker-service-token` must exist in Keychain before that profile starts. The original mount is read-only to the worker; its derived mount is writable only for generated asset keys. The worker image was tested locally with a read-only rootfs, native PDFium/Pillow import, a disposable named volume write, and a credentialed health probe. Keep native Chat disabled until API upload/publication and purge are connected; disabling the `chat-files` profile is the service rollback, while preserving private volumes for cleanup.

The API has owner-scoped original upload, attachment metadata and authenticated original download routes. Upload multipart fields are `filename`, `expected_revision` and `file`; the API validates metadata, limits the original to 10 MiB, locks owner/conversation quota, saves a generated-key original and records a queued immutable processing job plus an attachment event. Nginx permits an 11 MiB multipart envelope only on that upload path. Download returns the original as an attachment with `nosniff` and `no-store`; PDFs are never embedded as originals. Inspect `coire_chat_requests_total{operation="upload",outcome=...}` and attachment/job rows by generated IDs. Keep `COIRE_CHAT_ENABLED=false` until the remaining file UI, retry and visual gates pass. To roll back this slice, keep Chat off and restore the previous API/web images; retain private volumes until verified cleanup removes content.

The scheduler package includes a typed private worker client. It authenticates process/status/cancel calls with the dedicated mounted secret and returns only safe busy, missing or unavailable categories. An inspect request reserves one generated still-image asset ID; text and PDF results legitimately contain no asset for it. If worker status is missing after a crash, the workflow records a visible failure rather than silently parsing the original again.

The scheduler scans queued/running attachment jobs and starts a DBOS file workflow. Before its first worker POST it commits the generated output IDs, source digest and deadline in `chat_file_processing.output_manifest.request`. A recovering workflow queries `/v1/jobs/{job_id}` only. If the worker lost its in-memory status after a crash, the job fails with `worker_status_missing`; the owner may request one explicit retry after failed-output cleanup. A known 429 refusal retries within the original deadline. Inspect `coire_file_dispatch_total{outcome}` and `coire.scheduler.files.process` spans using `job_id`; no file content appears in logs. Deleting a conversation cancels running work and discards a late result. The scheduler stores a `processed` manifest for API verification. Keep `COIRE_CHAT_ENABLED=false` until the remaining gates pass. To roll back dispatch, restore the prior scheduler image with Chat still disabled; retain private volumes for cleanup.

API maintenance verifies processed manifests against the owning attachment, then reads each derived PNG from the private read-only mount through no-follow generated keys. Exact size, digest, PNG header and dimensions must match before an atomic ready update, quota shrink and `attachment.changed` event. A missing or altered output records `invalid_worker_output` and retains its quota reservation until cleanup; no derived asset becomes visible. Inspect `coire_chat_file_publication_total{outcome}` and `coire.api.chat.file_publish` spans by `job_id`. The derived mount is read-only in the API and writable only by the private worker. File UI and visual turn admission remain pending, so keep `COIRE_CHAT_ENABLED=false`.

Ready attachment metadata now lists generated preview IDs, dimensions and PDF page numbers. `GET /api/v1/chat/conversations/{conversation_id}/files/{file_id}/previews/{asset_id}` requires the same owner-scoped Chat identity as original download and rechecks the committed manifest plus PNG bytes on every read. It serves only inline PNG with `nosniff`, `no-store`, sandbox and same-origin headers; the original PDF remains a download attachment. A missing/changed preview returns a safe conflict and increments `coire_chat_requests_total{operation="preview",outcome="refused"}`. Do not put bearer tokens in preview URLs. File UI and visual turn admission remain pending, so keep `COIRE_CHAT_ENABLED=false`.

Deleted conversations now drive file erasure. After each job's hard deadline and a two-second grace, the scheduler marks it `purging`, then calls the worker's authenticated `DELETE /v1/jobs/{job_id}/output`; an active job is refused and retried. The worker deletes only a generated ULID output directory and succeeds if it was already absent, including after a worker restart. A successful call commits the job's `purged` marker and clears its result manifest. API maintenance waits for all attachment jobs to be purged, unlinks the generated original, deletes quota/job/attachment rows, then the existing text purge scrubs conversation content. A crash between unlink and DB commit is safe to retry. An hourly-age check removes only generated `.UUID.UUID.uploading` staging files. Inspect `coire_file_output_purge_total{outcome}`, `coire.scheduler.files.purge` spans and `coire_chat_requests_total{operation="file_purge",outcome=...}`. If a deleted conversation remains past the 24-hour deadline, inspect the pending-purge age alert and the job's `purging` state; restore worker availability before retrying. Keep Chat default-off until the remaining UI and coding/vision gates are complete.

Failed file conversions also enter a bounded output cleanup scan. The scheduler asks the worker to remove the failed job's generated directory and records `output_manifest.output_purged=true` only after success; `failed`, its safe error and attempt number remain visible. A busy or unavailable worker leaves the marker absent for retry. Inspect `coire_failed_file_output_cleanup_total{outcome}` and `coire.scheduler.files.failed_cleanup` spans by job ID. An explicit second attempt waits for this marker so crash remnants cannot share its reserved storage.

Owners can now POST `/api/v1/chat/conversations/{conversation_id}/files/{file_id}/process` with `request_id`, `expected_revision` and `operation: "inspect"` for one explicit second attempt. The route requires same-origin Chat authentication, the same owner/parent, a failed attempt-one job and its `output_purged` marker. It queues a new immutable attempt-two job using the unchanged original digest/key and rebinds the existing quota reservation; it does not call the worker directly. The same request ID and revision return the admitted attachment without another job. A second failure is terminal; reupload is required. Inspect `coire_chat_requests_total{operation="file_retry",outcome=...}` and the attachment/job rows. File UI and visual turn admission remain pending, so Chat stays default-off.

The same process route accepts `operation: "render"` with an explicit `selected_pages` list of one to ten pages from a ready PDF's verified page count. It expands the attachment's active reservation to cover up to 32 MiB of derived PNGs after owner/conversation quota checks, then queues a generated render job. A failed render can be retried once only after output cleanup and only with the same page list. Ready publication retains the prior page-attributed Unicode extraction as `asset_manifest.text_result` and publishes only the selected verified PNG pages as preview metadata; original PDF downloads remain attachment-only. Inspect `coire_chat_requests_total{operation="file_render",outcome=...}`. The file UI and visual turn/context admission remain pending, so keep `COIRE_CHAT_ENABLED=false`.

After failed-output cleanup, API maintenance shrinks the active file reservation to original plus any previously published derived bytes. Inspect `coire_chat_requests_total{operation="file_quota_reclaim",outcome="succeeded"}`. A later explicit inspect or page-render retry expands that same locked reservation to the 32 MiB derived bound before queueing; if another upload has used the freed owner/conversation capacity, the retry returns a quota refusal and leaves the failed file intact. A missing worker purge marker never releases quota. This avoids charging a failed, cleared conversion for bytes no longer stored while still bounding a new attempt.

The browser file panel uploads after creating a conversation, shows processing/failed/ready state and polls processing metadata every two seconds while the conversation is open. Owners can retry one failed inspection, download the original as an attachment, and view private PNG previews. For PDFs, select visual mode and numbered pages, then choose **Prepare selected pages**; the panel shows the included page list. The server remains authoritative for revisions and quotas, so a stale tab or exhausted quota shows the API refusal. Unready or visual selections disable Send; no selected file is silently sent as a text-only turn. Keep Chat default-off during this partial UI gate.

Ready text/code files and extracted PDF Unicode can now be selected for a text Chat turn. Admission verifies owner/conversation and published worker result identity, preflights the selected text with the full history, and stores the exact prompt snapshot separately from the displayed user text. A scanned PDF with no extracted Unicode returns a clear refusal in text mode; choose page images after image-capable Chat admission is available. The browser shows each sent file and content mode on its message. Image and visual page selections remain blocked before Send. Migration 0017 adds the prompt snapshot and selection columns; old messages retain their displayed text as prompt fallback. Keep `COIRE_CHAT_ENABLED=false` until visual, coding and final acceptance gates pass.

Same-tab Chat drafts now retain file IDs, modes and explicit PDF page numbers beside text/model choices, with a ten-file bound. Reopening a conversation revalidates these IDs and page counts against its owner-scoped detail before restoring them; missing choices produce a visible status. The session store serializes only those fields, never bytes, URLs or credentials. Identity change removes the former owner's draft store; accepted sends and conversation deletion remove the affected draft. These choices are browser-local and do not travel to another device or tab.

When the edge session expires, a Chat API or observer 401 shows **Sign in again** and stops observer reconnects. The link reloads the same origin through Cloudflare Access; the same-tab draft remains in sessionStorage until the returned `/me` identity is checked. A different owner clears the prior owner's store. Initial `/me` refusal gives the same sign-in action. Do not clear drafts merely because a session expires.

An authenticated user can choose **Sign out** from either shell. The browser removes that verified
owner's same-tab Chat drafts before navigating to Cloudflare Access's same-origin
`/cdn-cgi/access/logout` endpoint. This explicit action differs from session expiry, which retains
the draft for reauthentication. Cloudflare documents the application-domain logout route in its
[session management guide](https://developers.cloudflare.com/cloudflare-one/access-controls/access-settings/session-management/).

An owner can explicitly **Retry response** after the latest plain-Chat response failed, stopped or was interrupted. The previous partial assistant text remains in history. The retry keeps the original input and file choices, creates a new assistant attempt linked by `retry_of`, and checks model/file/context admission again; a stale or modified retry is refused. Later turns give the model only the latest answer attempt for that input, while owner history retains both attempts. A lost acknowledgement may repeat the same request ID to follow its saved events; it never starts another engine request.

When that latest terminal response has nonblank saved partial text, the owner can instead choose **Continue from partial answer**. It creates a separate fixed user instruction and assistant turn linked by `retry_of` with `recovery_mode: "continue"`; the original partial enters model context and stays visible. The separate editor draft is retained. A changed instruction, new files or stale target is refused. Inspect the owner-scoped turn and `coire_chat_requests_total{operation="send_terminal",outcome=...}` to diagnose either recovery path. Migration 0018 adds the nullable recovery mode; downgrade drops only that metadata. Keep Chat default-off until the remaining parent gates pass.

For models whose capability profile declares `thinking` or `hybrid`, Chat separates streamed `<think>` blocks and engine `reasoning_content` into persisted `reasoning` message deltas. The owner sees a collapsed **Reasoning** disclosure. Split delimiters are buffered and an unfinished reasoning block stays out of the answer. Inspect the owner-only turn events if output appears to stop inside a thinking block; do not copy reasoning content into telemetry or support logs. Models without declared reasoning retain plain answer streaming. Chat remains default-off until the other parent gates pass.

Fenced code has an explicit **Copy code** action using the browser clipboard; failure shows **Copy failed**. Markdown raw HTML and remote images remain inert, and executable or protocol-relative links are not clickable. This presentation change requires the web image only. Keep Chat default-off while the remaining acceptance gates are open.

Cold Chat turns now publish `queued` when the latest active model instance is requested or reserving and `loading` when it is launching or warming. The status follows actual placement transitions; no queue rank, percentage or unmeasured ETA is shown. Inspect owner-scoped turn events alongside model-instance transitions if the browser remains on **Waiting for capacity**. Stop and entitlement rechecks remain active during the wait. Chat stays default-off until the remaining gates pass.

The node now records `mlx_vlm` as a separate bare engine backend and launches it only from a verified local store copy, with offline mode, no inherited Hub token or remote-code trust, and one concurrent sequence/cache entry unless registry control supplies bounded values. The backend survives agent re-adoption; a conflicting text/VLM duplicate load returns a conflict. Migration 0019 stores this backend in the control-plane engine row and backfills existing text rows. Check node engine status and process records for the backend and reservation when diagnosing a failed visual load. Stop/unload the owned engine through the existing node control path; a node agent restart re-adopts a still-live process. Do not enable visual Chat until acquisition, context, gateway and tiny-model gates pass.

The native node install now consumes a lock-selected, hash-checked macOS arm64 wheelhouse and
checks both bare server CLIs before moving `envs/current`. See [model instance operations](instances.md#locked-native-node-environment)
for the build, install and rollback procedure. This smoke checks imports and command entry points
only; visual model acceptance remains a separate gate. Keep `COIRE_CHAT_ENABLED=false`.

The node's VLM readiness probe sends one token of text generation with the owned verified local
model path, as required by the pinned bare server endpoint. A health response alone is insufficient.
If a visual instance remains starting, inspect node process state and the generation probe result;
stop the owned engine through node control before retrying. Tiny-model acceptance is still open.

Until temporary image normalization and measured VLM visual budgeting are connected, the compatible `/v1/chat/completions` route returns 400 for inline image parts before spending tokens or contacting an engine. HTTP/file image URLs are rejected by the core wire schema. The `/v1/messages` adapter returns 400 for image or other unsupported Anthropic blocks instead of silently omitting them. Text parts remain available and count their full text in context preflight. Keep visual admission disabled until the remaining visual gateway and tiny-model gates pass.

The compatible OpenAI SSE boundary buffers a complete bounded engine event before replacing its
node-local `model` with the registry UUID. A malformed event or a private path in any other
published field closes the stream and records failed gateway usage. If a client sees an incomplete
stream without `[DONE]`, inspect the gateway's `engine_stream_failed` outcome and correlated
engine instance; do not forward raw engine output to users.
