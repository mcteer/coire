# ADR-0002: Name resolution on the Thunderbolt mesh via a managed hosts file

- **Status**: Accepted
- **Date**: 2026-08-29
- **Deciders**: Dan McTeer
- **Constitution**: exception to the Technology Constraints line "hosts are addressed by UniFi DNS names, never raw IPs, in any config"
- **Time-box**: none — revisit if a DNS service is ever placed on the mesh

## Context

All internal platform traffic rides the Thunderbolt mesh (`192.168.100.0/24`, measured
12.0–12.6 Gb/s, 0.85–1.37 ms). The mesh is unrouted by design and never reaches the UDM, so
UniFi DNS cannot serve names for it. mDNS was measured on 2026-08-29 and is non-deterministic:
from core, `coire-edge-a.local` resolved to a `169.254.x` link-local address; from edge-a,
`coire-core.local` did the same. Which interface answers changes as Thunderbolt interfaces
come and go.

The constitution forbids raw IPs in config so that hostfiles and compose files never
hard-code addresses. That intent must hold; the mechanism (UniFi DNS) cannot.

## Decision

- `deploy/cluster/hosts` is the single source of mesh addresses:

  ```
  192.168.100.10  coire-core.mesh
  192.168.100.11  coire-edge-a.mesh
  192.168.100.12  coire-edge-b.mesh
  ```

- The core bring-up script and the Studio node-prep script write it as a **managed block** in
  `/etc/hosts` on each host (`# BEGIN coire-mesh` … `# END coire-mesh`), replacing any prior
  block. This is config applied from `deploy/`, not hand-edited config on a node.
- **Every** service configuration, compose file, launchd plist and client references
  `<host>.mesh` names. A raw `192.168.100.x` *address* outside `deploy/cluster/hosts` fails
  review.

  One carve-out, added during implementation: `coire_core.models.node.MESH_SUBNET` names the
  subnet `192.168.100.0/24` so registration can reject an off-mesh address. That is a
  validation boundary, not a host address — membership cannot be checked without naming the
  range — and it is the single place the subnet appears in code. Renumbering the mesh means
  changing `deploy/cluster/hosts` and that one constant.
- Wi-Fi addresses are never written anywhere; the egress fallback uses `<host>.local`, which
  is adequate for a path that is explicitly degraded and alerted.

## Consequences

- One file to change if the mesh is ever renumbered; `/etc/hosts` blocks are regenerated by
  the same scripts.
- The `.mesh` suffix is a private convention, not a registered domain; nothing outside the
  three hosts can resolve it, which is the point.
- Feature 020 (failover) relies on this: mesh names keep resolving when core is down, which a
  DNS container on core could not guarantee.

## Alternatives rejected

- **mDNS** — measured non-deterministic across interfaces.
- **UniFi DNS** — the mesh never reaches the UDM.
- **A DNS container on core** — the mesh must keep working with core down.
- **Registration-time discovery only** — the node still needs core's mesh name to register.
